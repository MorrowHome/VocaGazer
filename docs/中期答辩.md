# VOCALOID Music Hub — 中期答辩

## 项目概述

**VOCALOID Music Hub**（虚拟歌手原创音乐数据平台）是一个专注于 VOCALOID 及 Synthesizer V 等虚拟歌手**原创曲目**的数据收集、分析与展示平台。

项目自动从 B 站采集虚拟歌手原创歌曲，通过加权评分系统生成排行榜，利用 AI 大模型生成每日数据分析报告，并提供社区论坛供用户交流。

### 核心定位

- **不是**单纯的 B 站视频搬运工具
- **不是**歌曲播放器
- **是**虚拟歌手原创音乐的**数据聚合与发现平台**
- **是**帮助用户发现优质原创曲目的**推荐引擎**

### 为什么选这个课题

VOCALOID 社区每天有大量原创歌曲发布，但缺乏一个集中展示和发现优质作品的平台。B 站的推荐算法偏向热门内容，新人和小众优质作品难以被发现。本项目通过自动化数据采集+多维评分算法+AI 分析，解决这个问题。

## 功能模块详解

### 1. B 站数据采集系统

**核心文件**: `src/server/services/bilibili/crawler.ts`

**工作原理**：
- 按 45+ 个虚拟歌手标签搜索 B 站视频（初音未来、洛天依、GUMI、flower、星尘 等）
- 去重合并：同视频命中多个标签时合并
- 三级过滤确保只收录原创歌曲

**原创性判定算法**：
1. 标题含"作曲""编曲""原创"等 → 直接判定为原创
2. 标题含虚拟歌手角色名 → 宽松认定为原创
3. 描述中含"作曲""produced by"等 → 认定为原创
4. 描述中含"本家：BVxxx" → 排除（翻调他人作品）

**关键词排除体系**（70+ 排除词）：
- 翻唱类：翻唱、翻填、cover、カバー
- 教程类：教程、教学、攻略、入门
- 游戏类：游戏、实况、直播、自制谱
- 合集类：盘点、合集、排行、榜单
- 影视类：片头、片尾、主题曲、BGM
- 媒体名：原神、崩坏、鬼灭、JoJo 等（含 V 家角色名时豁免）

**歌曲分类检测**：自动识别 original / remix / cover

### 2. 评分系统

**核心文件**: `src/server/services/ranking/scorer.ts`

加权综合评分算法：

| 指标 | 权重 | 说明 |
|------|------|------|
| 播放量 | 15% | 基础热度 |
| 点赞数 | 25% | 最高权重——反映用户认可 |
| 投币数 | 25% | 同权重——B 站特色指标 |
| 收藏数 | 20% | 反映长期价值 |
| 分享数 | 10% | 传播力 |
| 评论数 | 5% | 讨论热度 |

**公式**：
```
Score = 播放量 × 0.15 + 点赞 × 0.25 + 投币 × 0.25 + 收藏 × 0.20 + 分享 × 0.10 + 评论 × 0.05
```

### 3. 排行榜系统

**核心文件**: `src/server/services/ranking/generator.ts`

基于歌曲的**发布时间**过滤，确保时效性：

| 周期 | 歌曲发布时间范围 | 最大条目 |
|------|----------------|---------|
| 日榜 | 最近 1 天 | TOP 100 |
| 周榜 | 最近 7 天 | TOP 100 |
| 月榜 | 最近 30 天 | TOP 100 |
| 年榜 | 最近 365 天 | TOP 100 |
| 总榜 | 全部歌曲 | TOP 100 |

**快照机制**：
- 每天 00:30 自动生成所有周期的排行榜快照
- 日期选择器可查看任意日期的历史排行快照
- Ranking 表存储 `{period, rank, score, date, songId}`

### 4. 里程碑追踪

**核心文件**: `src/server/services/milestone/index.ts`

三个门槛：10 万 / 100 万 / 1000 万播放

**智能追踪机制**：
- 正常模式：爬虫入库时检查里程碑
- 接近模式（≥80% 进度）：加入监视列表
- 主动拉取模式（≥90% 进度）：定时任务每小时从 B 站 API 获取最新播放数据
- 高频检查模式（≥98% 进度）：极接近门槛时密集检查

每个里程碑记录精确达成时间和精确播放数。

### 5. AI 分析

**核心文件**: `src/server/services/ai/index.ts`

- 调用 DeepSeek 大模型（通过 Anthropic 兼容接口）
- 每天 20:00 自动生成音乐晚报
- 分析内容：今日数据亮点、近期趋势、歌曲/UP 主推荐
- 降级方案：未配置 API Key 时使用模板化文案

### 6. 数据分析页面

**核心文件**: `src/app/analytics/page.tsx`

- 总览统计：歌曲总数、UP 主数量、总播放量、平均评分
- 互动比率分析：点赞/播放比、投币/播放比等
- TOP 榜单：最高评分、最多播放、最高评分 UP 主
- 标签云：最热门标签
- 发布趋势图：按月/按周
- 评分分布图
- 时间范围过滤：7 天 / 30 天 / 90 天 / 全部

### 7. 定时任务调度

**核心文件**: `src/server/services/scheduler.ts`

| 任务 | 周期 | 说明 |
|------|------|------|
| 数据采集 | 每 6 小时 | 增量采集最近 48 小时视频 |
| 排行榜生成 | 每天 00:30 | 5 个周期快照 |
| AI 晚报 | 每天 20:00 | DeepSeek 生成 |
| 里程碑扫描 | 每小时 | 主动拉取接近门槛歌曲 |

### 8. 其他功能

- **用户系统**：JWT 注册/登录，用户角色管理
- **社区论坛**：发帖回帖，分类为乐评/推荐/讨论/提问
- **推荐页**：编辑推荐 + 热门推荐 + 最新发布
- **歌曲详情**：展示所有统计数据，跳转 B 站观看

## 数据库设计

### ER 关系

```
Song ──1:N── SongDailyStats    (每日统计快照)
Song ──1:N── Ranking           (排行榜条目)
Song ──1:N── SongMilestone     (播放量里程碑)
User ──1:N── Post              (论坛帖子)
Post ──1:N── Reply             (回帖)
```

### 核心模型字段

**Song 表** (歌曲主表)：
- bvId (B站视频ID, 唯一)
- title, author, description, duration
- picUrl (封面), tags (JSON 数组)
- publishTime (发布时间)
- score (综合评分), statistics (JSON 统计)
- category (分类: original/remix/cover)

**Ranking 表** (排行榜快照)：
- period (周期), rank (排名), score (评分)
- date (快照日期), songId (外键)

**SongMilestone 表** (里程碑)：
- threshold (门槛), achievedAt (精确达成时间)
- playCount (精确播放数), songId (外键)

**SongDailyStats 表** (每日统计)：
- date, playCount, likes, coins, favorites, shares, comments, score

## 关键技术难点

### 难点 1：非原创内容过滤

B 站搜索"初音未来"返回大量翻唱、教程、MMD、游戏实况。解决方案是三层过滤：
1. 70+ 排除关键词
2. 原创性判定算法（标题/描述关键词匹配）
3. 时长过滤 + VOCALOID 标签验证

同时设计了媒体名豁免机制，避免含 V 家角色名的游戏联动曲被误杀。

### 难点 2：排行榜时效性

排行榜需要按发布时间范围筛选（而非全量排序），同时要支持查看历史数据。采用快照机制：每天生成各周期 TOP 100 存入 Ranking 表，前端日期选择器查询历史快照。

### 难点 3：里程碑精确追踪

爬虫每 6 小时运行，无法捕捉歌曲达标的精确时刻。采用分阶段策略：正常(自动检查) → 接近80%(加入监视) → 主动拉取90%(每小时API) → 高频98%(密集检查)，记录精确时间和播放数。

## 部署方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| VPS 直接部署 | 完全可控，定时任务稳定 | 需 Linux 基础 |

```
git pull → npm install → npx prisma db push → npm run build → pm2 restart
```
