  三、完整部署流程（浓缩版）

  等你服务器到手后，按这个顺序走：

  1. SSH 连上服务器

  ssh root@你的IP

  2. 一条命令装好环境

  apt update && apt upgrade -y
  curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
  apt install -y nodejs git nginx

  3. 把代码传到服务器

  两种方式：
  - 公开仓库：git clone 你的仓库 /opt/vocaloid-hub
  - 私有仓库：在服务器上配好 SSH key 再 git clone，或者本地 scp -r 传上去

  4. 创建 .env

  cd /opt/vocaloid-hub
  nano .env
  内容参考本地 .env 文件（注意把 API key 填对）。

  5. 构建并启动

  npm install
  npx prisma db push
  npm run build
  npm install -g pm2

  pm2 start node_modules/.bin/next --name vocaloid-hub -- start
  pm2 save
  pm2 startup  # 按提示执行那行命令

  6. 配置 Nginx + SSL（关键步骤）

  # 配置反向代理
  nano /etc/nginx/sites-available/vocaloid-hub

  写入（替换你的域名）：
  server {
      listen 80;
      server_name 你的域名.com;

      location / {
          proxy_pass http://127.0.0.1:3000;
          proxy_http_version 1.1;
          proxy_set_header Upgrade $http_upgrade;
          proxy_set_header Connection "upgrade";
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
      }
  }

  ln -s /etc/nginx/sites-available/vocaloid-hub /etc/nginx/sites-enabled/
  nginx -t && systemctl restart nginx

  # 免费 SSL
  apt install -y certbot python3-certbot-nginx
  certbot --nginx -d 你的域名.com

  7. DNS 解析

  去你的域名注册商（或 Cloudflare），添加一条 A 记录：
  - 主机记录：@ 或 www
  - 记录值：你的服务器 IP

  等几分钟生效后，访问 https://你的域名.com 就能看到了。

❯ vps的kvm是什么意思                                                            

⏺ KVM 是 Kernel-based Virtual Machine（基于内核的虚拟机）的缩写。

  简单说，它是一种虚拟化技术，决定了你的 VPS 是怎么"切"出来的：

  ┌────────────────┬───────────────────────┬────────────────────────────────┐
  │   虚拟化类型   │         原理          │              特点              │
  ├────────────────┼───────────────────────┼────────────────────────────────┤
  │ KVM（硬件级）  │ 直接虚拟化物理硬件，  │ 性能好，资源独享，可自定义内核 │
  │                │ 每个 VPS 有独立内核   │                                │
  ├────────────────┼───────────────────────┼────────────────────────────────┤
  │ OpenVZ（容器级 │ 共享宿主机内核        │ 性能差，有超售风险，不能改内核 │
  │ ）             │                       │ 参数                           │
  ├────────────────┼───────────────────────┼────────────────────────────────┤
  │ LXC/LXD        │ 也是容器级            │ 类似 Docker，但隔离性不如 KVM  │
  └────────────────┴───────────────────────┴────────────────────────────────┘

  买 VPS 时，认准 KVM。 同样 2 核 4G 的配置，KVM 的实际性能比 OpenVZ
  好很多，因为：
  - CPU、内存是独享的，不会被邻居抢
  - 可以自己装任意系统内核（比如开启 BBR 加速）
  - 宿主机超售情况一般比 OpenVZ 好

  大部分正规厂商（Hetzner、阿里云、腾讯云、DigitalOcean、搬瓦工 等）默认都是
  KVM。如果看到没写虚拟化类型，问一句客服确认一下，避开 OpenVZ 就行。

❯ kvm还是AMD还是Windows                                                         

⏺ 这三个是不同维度的东西，不是互斥的选项：

  - KVM — 虚拟化技术（决定你的 VPS 性能好不好）
  - AMD — CPU 品牌/架构（物理芯片）
  - Windows — 操作系统（装什么系统）

  买 VPS 时，正确的组合是 KVM + AMD + Linux：

  - 虚拟化：选 KVM（不是 OpenVZ 就行）
  - CPU：选 AMD 还是 Intel 无所谓，谁便宜选谁。现在很多厂商 AMD EPYC 性价比更高
  - 系统：你是 Ubuntu 24.04，不是 Windows。Windows
  要额外付授权费而且吃内存，这个项目完全不需要

  所以你的选择就是：KVM 虚拟化 + AMD 处理器 + Ubuntu 
  系统，这三者可以同时成立，不矛盾。

❯ debian还是ubuntu                                                              

⏺ 如果这是你第一次部署网站，推荐 Ubuntu 24.04。

  原因很简单：

  ┌──────────────┬─────────────────────────────┬──────────────────────┐
  │    对比项    │           Ubuntu            │        Debian        │
  ├──────────────┼─────────────────────────────┼──────────────────────┤
  │ 包版本       │ Node.js、Nginx 等软件包更新 │ 偏保守，稳定但版本老 │
  ├──────────────┼─────────────────────────────┼──────────────────────┤
  │ 教程资源     │ 网上教程绝大多数用 Ubuntu   │ 相对少一些           │
  ├──────────────┼─────────────────────────────┼──────────────────────┤
  │ 日常操作     │ apt 跟 Debian 一样          │ 一样                 │
  ├──────────────┼─────────────────────────────┼──────────────────────┤
  │ 对你这次部署 │ 直接按文档走就行            │ 可能需要小调整       │
  └──────────────┴─────────────────────────────┴──────────────────────┘

  实际差别非常小，两个都是 Debian 系，命令几乎一样。但 Ubuntu 的 Node.js
  源、certbot 等软件版本更新，教程也多，对第一次部署更友好。

  选 Ubuntu 24.04 LTS，走到哪都不踩坑。

⏺ 从日志看，里程碑扫描已经在运行了（有 开始扫描里程碑
  的记录）。但你设的北京时间对应到服务器 UTC 时间有偏移：

  ┌──────────┬──────────────┬────────────────────────────┐
  │   任务   │ 期望北京时间 │       实际 UTC 触发        │
  ├──────────┼──────────────┼────────────────────────────┤
  │ 采集     │ 8/14/20/2 点 │ 0/6/12/18 UTC              │
  ├──────────┼──────────────┼────────────────────────────┤
  │ 排行榜   │ 8:30         │ 0:30 UTC                   │
  ├──────────┼──────────────┼────────────────────────────┤
  │ AI 晚报  │ 20:00        │ 20:00 UTC (凌晨4点北京) ❌ │
  ├──────────┼──────────────┼────────────────────────────┤
  │ 全量刷新 │ 11:00        │ 3:00 UTC                   │
  └──────────┴──────────────┴────────────────────────────┘

  最简单的方案——把服务器时区改成北京时间（东八区），这样所有定时任务就按你期望的
  时间触发：

  timedatectl set-timezone Asia/Shanghai
  pm2 restart vocaloid-hub

  改完后验证：

  timedatectl

  然后 pm2 logs vocaloid-hub --lines 10
  看看重启后的日志，确认定时任务的输出变成北京时间。

⏺ 服务器上也有这些脚本。你现在 SSH 连着的，手动爬虫：

  cd /opt/vocaloid-hub
  bash crawl.sh --today

  这会采集最近 24 小时的新歌。也可以用：

  - bash crawl.sh — 最近 72 小时
  - bash crawl.sh --week — 最近一周

  另外还有排行榜手动生成：

  npx tsx scripts/generate-ranks.ts

  建议先改时区再跑手动采集，这样下次定时触发时间也对了：

  timedatectl set-timezone Asia/Shanghai
  pm2 restart vocaloid-hub
  bash crawl.sh --today
